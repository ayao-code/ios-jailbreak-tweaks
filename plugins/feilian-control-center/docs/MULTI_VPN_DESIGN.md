# VPN 控制中心：Easy VPN / 飞连设计

**历史设计快照**：下面“两提供方、切换确认、旧连接停止失败不启动新目标”
已被用户后续确认的 silent1 交互替代。当前五提供方、普通点击不跳 App、
长按直接切换和 8 秒软停止窗口以 `SILENT_SWITCH_STATUS.md` 为准。

状态：设计完成，未实现、未安装。日期：2026-11-14。
更新：本行是设计定稿时的快照；后续 1.3.0~candidate1 已开始实现并临时
安装验证，最终回滚。当前进展与未完成项以 `CANDIDATE1_STATUS.md` 为准。
目标环境：当前 iPhone 12 mini / iOS 16.3.1 / RootHide；其他环境不承诺。

## 1. 目标与范围

升级现有“飞连 VPN 控制中心”为“VPN 控制中心”，仍只有一个 1×1 按钮。
首次默认 Easy VPN，轻点连接/断开，控制中心内长按选择 Easy VPN 或飞连，
记住用户选择。优先后台调用各 App 的原生连接流程，不自动打开 App 界面。

本版仅支持两个已明确的 App，不做任意 App/节点/协议管理，不替用户登录、
选择节点、购买、认证或安装 VPN 配置，不做 daemon、保活或网络健康轮询。
“切换 VPN”指切换 App 提供的连接，不是切换 Easy VPN 内部的服务器节点。

## 2. 交互

### 收起：一个按钮

- 灰色盾牌：当前无受支持连接；轻点连接用户选择的目标。
- 蓝色盾牌：系统确认某个受支持 VPN 已连接；轻点断开这个实际连接。
- 连接/断开中：有限进度反馈，不把连接中当作已连接；拒绝重复提交。
- 感叹号：最近一次操作失败；长按查看简短原因与下一步。
- 状态未知：不显示成“已断开”，初始化完成前禁止连接操作。

若用户从 App 手动连接飞连，即使记住的选择是 Easy VPN，按钮也显示真实
飞连状态，轻点断开飞连；不会误启动 Easy VPN。业务连通与蓝色不是同义词。

### 长按：系统展开面板

```text
VPN 控制中心
下次使用：Easy VPN
当前：未连接

✓ Easy VPN       未连接
  飞连           未连接

打开 Easy VPN
最近结果：连接已断开
```

勾选代表记住的选择；每行状态代表系统真实状态，两者独立。
App 未安装、配置不唯一、扩展不可用时显示具体原因并禁用连接操作。
无法证明注入已开启时不能断言“注入未开启”；辅助握手未收到时提示
“连接辅助未响应，请检查 App List 和 App 版本”。
“打开 App”仅由用户明确点选后执行，用于原生登录/权限处理，不自动兜底跳转。

| 当前状态 | 选择另一行的结果 |
| --- | --- |
| 无活动 VPN | 只保存选择，不立即连接；下一次轻点启动它 |
| 所选项已是记住的目标且无连接 | 无网络操作、无重复写入 |
| 当前实际连接就是该行 | 保存选择，不断开重连 |
| 另一个受支持 VPN 活动中 | 面板内显示切换确认；取消不改网络或选择 |
| 其他不受支持 VPN 活动中 | 拒绝启动/替换，提示用户自行关闭；允许查看，不自动断开 |
| 本模块请求进行中 | 允许查看状态，禁止提交新连接或切换 |

切换确认文案：“断开飞连并连接 Easy VPN？切换期间网络会短暂中断。”
两个方向同样处理。确认只授权当时明确显示的两份配置；确认后状态变了，
重新检查并拒绝旧确认，不扩大为“可关闭任何 VPN”。
不受支持 VPN 的情况下，用户仍可退出面板到 App 自行处理。

## 3. 状态与切换事务

三个概念分开维护：`preferredProvider`（记住的目标）、`activeProvider`
（系统实际活动配置）、`operation`（本模块当前请求）。UI 不推断系统状态。
`activeProvider` 可为 none / easy / feilian / external / ambiguous / unknown。

状态：loading → idle → launching → connecting → connected；
connected → disconnecting → idle；任意失败回到真实状态并保存简短错误。
failed 是操作结果，不覆盖仍连接着的系统状态。

确认切换的顺序：

1. 检查目标 App/配置/扩展、辅助可用性、锁屏状态和当前系统连接；捕获
   精确 source/target 配置身份和 generation。校验失败时不动旧 VPN。
2. 创建单一事务，断开用户确认的 source。只接受系统确认已断开；
   请求派发或辅助“已处理”不等于已断开。
3. 再检查目标身份与其他活动 VPN。出现外部新连接、配置变化或锁屏时
   停止，不启动 target，不关闭新出现的连接。
4. 后台唤醒 target App，发起原生连接请求；等待辅助结果和系统状态。
5. 系统确认精确 target 已连接且辅助未报失败后才保存新选择。

断开 source 失败：不启动 target，选择保持原值。
target 连接失败：不自动重连 source；明确提示“旧连接已断开，新连接失败”，
按钮显示真实状态，选择仍为切换前值。自动回滚会重新触发认证并扩大副作用，
不纳入本版。此时网络可能没有 VPN，不用“切换失败”模糊掩盖。
若选择保存失败，网络成功不作废；面板说明选择未保存，不假装下次默认已变。

关闭控制中心仅释放视图订阅，不取消用户已经确认的连接请求。
请求 pending 时禁止新请求；取消/超时后不能允许旧任务迟到启动新的连接。
所有完成回调按 generation + provider + profile 身份校验，旧回调只丢弃，
不能清除新请求的通知状态或修改新连接。

## 4. 实现结构：少量固定组件

### 控制中心宿主

- 保留 `ayao.feiliancontrolcenter.module` 和原 bundle/Package ID，升级而不是
  新增模块；设置显示名改为“VPN 控制中心”，保留原控制中心位置和顺序。
- 用自定义 `contentViewController` 提供收起按钮与展开面板；优先核对
  iOS 16 的 CCUIMenuModuleViewController，方法不兼容时使用实现
  CCUIContentModuleContentViewController 的最小自定义控制器。
- 只在本模块视图内处理展开，不 Hook 全局控制中心长按，不增加覆盖窗口。
- `VPNController` 在串行队列内拥有状态机、配置枚举和事务；UI 主线程只
  更新快照，不做同步 App 启动、等待隧道或配置加载。
- 两个固定 provider 记录 + 一个 adapter 协议，不引入注册中心或插件框架。
  FeilianAdapter 复用既有连接流程，EasyAdapter 复用已实测的原生按钮流程。

### App 专用辅助

- FeilianConnectHelper Filter 仍仅 com.volcengine.corplink。
- EasyVPNNativeHelper Filter 仍仅 com.qdtiktok.easyvpn，不包含其 VPN 扩展、
  SpringBoard 或任何其他 App；扩展继续由 App 原生流程启动。
- Easy VPN 调用原始 startButtonClick:，保留 App 判断，不直调 prepareStartVPN
  或构造/提取启动参数。可用正式版采用系统接口断开目标，避免只为断开唤醒
  App；已实测原生 stopButtonClick: 保留为诊断/必要适配依据，系统断开需补验。
- 唯一明确目标的原生 Session 可用于状态确认，不能把一个 App 的多个配置
  静默选取为 firstObject。
- 背景启动失败/辅助不可用时不前台兜底，面板提供用户主动“打开 App”。

建议新增 `VPNController.h/.m`、`VPNModuleViewController.h/.m` 和 EasyAdapter
的少量源码；适配器若很短可在控制器同文件实现。正式 Makefile 纳入 Easy
辅助，独立 probe 不打入正式包；飞连旧源及历史回滚包保留。

## 5. 请求、安全和生命周期

- 正式请求协议独立于 test1：版本、generation、明确动作、目标和到期时间；
  不包含节点、Token、账号或 Keychain 数据。默认建议 Easy 连接 30 秒、
  飞连连接 15 秒、目标断开 10 秒；切换的两个阶段分别计时，值是设计建议，
  不是已验证极限或耗时 SLA。
- 系统状态通知更新，不持续轮询；首次枚举的异步初始化必须作为 loading
  阶段处理，未完成加载不能把空列表/默认状态当断开。有限预热需有明确
  readiness 证据，不能仅把实验工具的等待秒数搬进 UI。
- Darwin 通知只作唤醒，不是身份认证。正式跨进程入口必须验证请求来源和
  新鲜度，仅允许本模块宿主发起；实施前核对可用的带来源校验 IPC/审计令牌，
  不能把公开通知名加时间戳当权限校验。test1 未提供此保证，不直接发布。
- 超时/取消：停止本次明确创建的目标连接，等待真实停止；释放背景任务、
  observer、timer。不能停止外部启动的 Session，不能在辅助报错时关掉非目标。
- Easy 原生任务可能迟到执行 enableVPN:；正式辅助必须能将它绑定到本次
  request generation 并在启动前拒绝已取消任务，同时保持普通手动连接路径。
  识别/取消不到本次原生任务，就不能宣称超时安全，属于发布阻塞。
- 原生认证/付费/权限 UI 不自动点击、不压掉后强行续连。需要交互时请求
  明确失败，保留 App 自身决定；“后台且不切前台”的行为必须独立验收。
- 不改 RootHide App List 或签名信任；安装前检查并提示目标注入前提。
  阿里/蚂蚁、银行/支付/证券及京东 App 始终不在任何 Filter 中。

## 6. 持久化与升级

只保存版本号和 `preferredProvider`（easy / feilian），使用本模块独立
preferences domain 的官方 CFPreferences API。没有连接状态、配置 UUID、
凭据、地址或 App 内部节点。原生 App 配置和 RootHide 配置不直接改写。

没有设置记录时默认 Easy；目标不可用时保留 Easy 并解释原因，不悄悄换飞连。
首次升级时若飞连已连接，按钮显示/控制实际飞连，不自动断开；无活动连接
之后默认按 Easy。用户选过飞连后长期记住，重启/刷新不强制改回 Easy。
读取损坏/未知枚举时用 Easy 默认值，显示必要提示，不扩大目标。

计划正式版本为 1.3.0，待实现和验收后才更新 control、Info.plist 和 README。
试验辅助包不与正式包并存重复加载：安装前核对并迁移/卸载 test package，
正式包内提供两份精确辅助。所有 deb 继续放父项目 packages，源码完整保留。
升级不重写 ModuleConfiguration.plist；必要的模块注册修复另行授权和备份。
卸载只移除本包文件，不还原整份旧配置、不自动关闭用户的 App List 设置。

## 7. 当前证据与交付门槛

已实测：Easy VPN 2.1.0 在 12 mini 上两轮断开/重连；冷启动后台连接；
后台重连；四次 HTTPS 200 / Success，15 秒后仍 connected。重连约 4.23 秒，
后台冷启动约 5.73 秒。见 `../tests/EASY_VPN_NATIVE_VALIDATION.md`。
HTTPS 通过不证明指定 VPN 出口；前台不变性未取得可靠证据。

设计参考的系统 SDK 声明支持模块扩展、导出菜单控制器类；并不证明
本机运行时方法、长按动画或实际控件兼容。以下均是后续验收，不是已通过：

1. 真正控制中心轻点默认 Easy，长按展开/收起、选择记忆及横竖屏展示；
   UI 回调目标小于 50ms，不同步等待连接；这是验收目标而非当前数据。
2. Easy 与飞连各至少两轮真实轻点连接/断开，系统读回、实际网络请求与
   对应 App 状态一致；前后台/冷启动分别记录，视觉检查不切前台边界。
3. Easy→飞连、飞连→Easy 的确认/取消/两阶段失败；外部 VPN 出现时保护，
   旧连接失败不得启动新连接；连接失败不自动回滚或保存假成功选择。
4. 唯一/多个/不存在配置、App 未安装、注入关闭、辅助未响应；初始加载
   不误判断开，App 手动开关后按钮及时显示真实状态。
5. 锁屏、认证过期、权限/付费提示、取消和迟到回调；来源校验、并发请求、
   请求 generation 隔离和 App 原生普通连接不受影响。
6. 安装/升级/卸载：原模块位置、四份 RootHide 配置、高敏 App 隔离保持；
   两个 App 和 SpringBoard 无新增崩溃；检查后台任务结束和空闲资源使用。

任何来源校验、取消安全、控件兼容或高敏隔离检查失败，停止发布，保留
诊断结果；不将编译或独立 probe 成功当作正式控制中心验收通过。
