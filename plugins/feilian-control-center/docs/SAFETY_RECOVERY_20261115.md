# silent5 崩溃后的安全止损修复

日期：2026-11-15。目标 iPhone13,1 / iOS 16.3.1 / RootHide。
用户要求继续修复并报告五个 VPN 状态，本轮首先处理风险，未继续发连接命令。

## 开始与最终状态

开始回读手机为 silent5、安全模式标记不存在、unlocked=1，五份 VPN 全断开，
旧自动测试组件已移除。本轮替换为 1.3.0~silent6-safety1 并刷新生效。
最终仍为已解锁、无安全模式、五份 VPN 全断开，认证服务由 launchd 正常运行。
四份 RootHide 隔离配置与本轮开始时字节完全一致，没有注入高敏 App。

## 风险来源与修复

前一轮为处理 RunningBoard 因断言过期未确认而终止 GOFast 的问题，采用
动态 BKSProcessAssertion 子类及新的 reason。实际构建返回 nil，后续
objc_setAssociatedObject 写入空对象使 SpringBoard 崩溃。空检查补丁只编译
不能证明子类/生命周期兼容，本轮改为更小范围的止损方案：

- 移除动态子类和 associated callback，不继续使用未验证的 reason。
- 使用已实测系统 BKSProcessAssertion / FinishTask reason=4。
- 创建失败立即关闭本次 IPC；不给 nil 安装 callback，不降级为无认证执行。
- 生命周期计数防止取消过程中建立的新 socket 被重新标为有效。
- 对断言同步单次取出，主队列失效；socket 关闭中断 I/O，不复用在途 descriptor。
- 15 秒主动安全到期释放断言并关闭本次 IPC，避免继续持有超出系统预算的请求。
- 旧定时器绑定生命周期及弱断言对象，不会关闭后续新的 request。

这是安全止损候选，不是保证所有较慢 VPN 都能在 15 秒内连接的完整修复。
超过预算将失败关闭；没有为了连接成功而无限保活、忽略系统过期或关闭沙盒。

## 本轮实际回归

测试均在真正 SpringBoard 使用手机已安装模块的同一 VPNIPCClient，只
后台唤醒 Easy 并 probe，不发送连接/断开命令。一次性工具不随插件包安装。

| 回归 | 最终包结果 |
| --- | --- |
| 已认证 client 两个 worker 同时 close | 10/10 完成，ready_count=10，共20次 close |
| 主动到期后再次 probe | 2/2 失败关闭，lease_expired_closed=1 |
| 到期后并发 close | 2/2 完成，没有二次失效崩溃 |
| SpringBoard CrashReporter 报告增量 | 本轮新增0，不删除以前报告 |
| 安全模式 | 本轮未出现 |
| 安装版本 | dpkg 回读 silent6-safety1 |

两种回归均取得 ASSERTION_CLOSE_STRESS_DONE=1，没有把启动成功或部分轮次
当作完成。回归只证明当前观测窗口内的安全路径，不承诺永久没有崩溃。

## 五目标功能状态

Easy、飞连、Hotspot 在以前版本的后台网络/停止/切换已有通过记录。
Jump 后台原生连接及停止有多轮成功，但 HTTPS 有超时。GOFast 有后台
成功闭环，但重复请求曾出现原生前置拒绝、协商超时及系统终止。
这些结论不能直接用于 silent6-safety1：本轮五 App 连接/断开/网络测试未执行，
也没有真实控制中心点按/长按、视觉或全面安全验收。
圆形进度居中属于先前布局实测，不代表本安全候选已重新做视觉验收。
