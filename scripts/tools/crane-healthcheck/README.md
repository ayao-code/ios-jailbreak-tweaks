# Crane native health check

Short-lived, standalone Objective-C executable. Calls only the installed
Crane helper's `verifyCraneInsuranceAndReply:` and
`verifyCraneSBLoadedAndReply:` via its native XPC proxy. No debugger attachment,
injection fix-up, restarts, application launches, container changes or data
exports. Five-second timeout per query. JSON includes booleans, broken daemon
names and error domain/code only.

Callback signatures were confirmed from Crane 1.3.18-2's extended Objective-C
protocol metadata. Reconfirm against the target version before reuse.
Build with `sh build.sh /absolute/output/directory`. This uses arm64,
Foundation, manual reference counting and the included standalone entitlements.
Manual reference counting avoids newer ARC imports generated by the Mac
compiler; this is a one-shot process, not reusable resident code. Add an
`@executable_path/.jbroot/usr/lib` rpath and a `.jbroot` link to the device's
verified physical jailbreak root. Run only on an authorized target.

Passing self-check proves daemon coordination, not full per-app container,
Keychain, push isolation, or compatibility with every application.

Verified on 2026-11-08: iPhone13,1, iOS 16.3.1 / 20D67, RootHide,
Crane 1.3.18-2. Native insurance and SpringBoard checks both returned true,
with no broken daemons. No application container switch was performed.
