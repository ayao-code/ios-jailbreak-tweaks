# 完整越狱与恢复流程：源机只读 → 巨魔 → 越狱 → 隔离 → 目标覆盖

> 整理日期：2026-11-19。本文是本仓库的总入口，统一已有教程的执行顺序。
> 主线针对本次 iPhone 14 Pro Max / iOS 16.3 和 iPhone 12 mini / iOS 16.3.1
> 使用 TrollStore 安装 Dopamine／RootHide 越狱 App 的路线，不推广到所有 iOS。
> 本文整理不代表再次安装、备份或验证手机；历史结果与通用操作步骤分开记录。

## 一、先看完整顺序

**当前路线：源机只读、确认目标覆盖范围 → 安装并确认巨魔可用 → 用巨魔安装越狱 App →
打开越狱 App 执行越狱 → 确认越狱环境 → 配好高敏 App 隔离 →
恢复 App、插件源、插件与设置 → 恢复控制中心和桌面 → 验证、收尾。**

TrollStore 与越狱不是同一个能力，但在本文选定路线中，巨魔承担安装越狱 App
的前置步骤。安装了巨魔，或者在桌面上看到 Dopamine 图标，都不等于已经越狱。
必须在越狱 App 内执行 Jailbreak，并确认本轮启动后的越狱环境确实可用。

```text
确认设备、系统、用户目标、安装器支持范围
                    ↓
源机只读；锁定目标覆盖范围（另行灾备操作按需备份）
                    ↓
原生数据恢复（仅确实需要换机／抹机恢复时；另行授权）
                    ↓
已有同环境越狱？ ── 是 → 检查是否已激活；必要时重新越狱
         │ 否
         ↓
旧 rootless 转 RootHide？ ── 是 → 官方路径移除旧越狱环境
         │ 否                         │
         └───────────────┬─────────────┘
                         ↓
已有可用巨魔？ ── 否 → 按系统选择官方安装路线，安装 Helper／TrollStore
         │ 是                         │
         └───────────────┬─────────────┘
                         ↓
确认 TrollStore 和 Persistence Helper 可用
                         ↓
用巨魔安装所选、已核对的 Dopamine／RootHide IPA/TIPA
                         ↓
打开越狱 App → Jailbreak → 确认本轮激活、包管理器及实际根目录
                         ↓
高敏 App 黑名单／禁注入配置及回读（首次启动高敏 App 前）
                         ↓
恢复需要的普通 App / TrollStore App（只装明确缺失项）
                         ↓
软件源 → 依赖／插件（分批）→ 覆盖目标设置
                         ↓
控制中心（模块先齐）→ 桌面（按当前 App 清单生成）
                         ↓
目标必要重载 → 配置／运行／视觉核验 → 精确清理、保留源导出与报告
```

**支持范围或设备身份不明，就不进入写入。换机配置恢复不要求双端备份或目标旧配置备份；抹机、移除环境和数据操作另行确认灾备要求。**
无需换机或抹机时，跳过原生数据恢复，不为了越狱主动升级 iOS 或抹除手机。

## 二、这些工具分别负责什么

| 名称 | 本流程中的职责 | 不代表什么 |
| --- | --- | --- |
| TrollRestore／TrollInstallerX 等安装器 | 按受支持路线安装 TrollStore 或它的安装 Helper | 不直接证明越狱已激活 |
| TrollStore（巨魔） | 安装所选越狱 IPA/TIPA，以及已授权的其他 IPA | 不直接提供 SSH、SpringBoard tweak 或 root |
| TrollStore 安装 Helper | 首次安装 TrollStore 的入口 | 不等于已正确配置 Persistence Helper |
| Persistence Helper | 图标缓存／注册状态变化后恢复 TrollStore 及其 App 的可启动状态 | 不负责重新执行越狱 |
| Dopamine／Dopamine RootHide | 越狱 App，执行 Jailbreak 并建立本轮越狱环境 | App 安装成功不等于 Jailbreak 成功 |
| RootHide Manager | 管理相应版本支持的隔离、黑名单和配置 | 不等于包转换器；不保证所有 App 检测不到越狱 |
| Sileo 等包管理器 | 安装源、依赖、DEB 插件 | 图标存在不证明数据库、架构和依赖正确 |
| RootHide Patcher | 必要时转换支持的旧包到目标环境 | 不是修改 control 架构就能兼容，也不是所有包都能转 |
| TrollFools | 用户单独授权后的 App 内 dylib 注入工具 | 不是恢复插件所必需，也不受黑名单自动撤销 |

普通 Dopamine rootless 与 RootHide 是两个目标环境；同名／同版本插件不意味着
同一个包能通用。本仓库普通 rootless 包约定 `iphoneos-arm64`，RootHide 包约定
`iphoneos-arm64e`。这两个包架构标签也不等于 Mach-O CPU slice 必然相同。

## 三、按现状选路线，不重复安装

| 当前状态 | 从哪里开始 | 不应做的事 |
| --- | --- | --- |
| 新目标，巨魔和越狱都没有 | 源机只读／支持核验 → 巨魔 → 安装越狱 App → Jailbreak | 不直接装插件，不假定 SSH 已有 |
| 巨魔可用，但没有越狱 App | 源机只读／支持核验 → 用巨魔安装所选越狱 App | 不重装巨魔或 Helper |
| 越狱 App 已有，手机重启后未激活 | 按该版本要求重新执行 Jailbreak，核对激活 | 不因此刷机、重装全部包 |
| 已有并已激活相同 RootHide 环境 | 现场盘点 → 隔离核验 → 选择性恢复 | 不移除现有正常环境 |
| 普通 rootless 转 RootHide | 四层备份 → 官方移除旧环境 → 核对巨魔 → 安装目标越狱 App | 不把旧 `/var/jb` 整体盖到新根 |
| 系统／机型不支持所选路线 | 停止，查官方对应版本文档 | 不试探写入，不把其他手机成功当兼容证明 |
| 需要 Apple 原生数据灾备恢复 | 单独确认范围与系统升级风险；通常安排在越狱配置之前 | 不把 Finder“恢复 iPhone”和“恢复备份”混同 |

## 四、阶段 0：身份、支持范围和工具来源

### 0.1 固定目标身份

先用 Finder 或可信 USB 配对读取 ProductType、ProductVersion、BuildVersion。
多台手机连接时，用当前确认的设备标识选定目标，不能只认 IP 或“第一个设备”。

可用时只读查询：

```sh
pymobiledevice3 usbmux list
pymobiledevice3 lockdown info
```

不同工具版本的参数可能不同，先查 `--help` 并明确选设备。当前序列号／UDID
只写私有运行记录，不写公开文档。手机未配对／未信任时，由用户正常解锁授权。

### 0.2 支持是分层的

分别核验：TrollStore 是否支持该系统、所选安装器是否支持该系统／Build、
越狱发布包是否支持该芯片／系统。三者不能互相代替。
本次 iOS 16.3／16.3.1 是历史操作范围，不是支持全部现代系统的结论。

只从原作者入口取得发布包，固定版本和 SHA-256，保留 release 说明。
当前上游分支可能已是新一代实现，不能把最新 README 的范围直接套给旧安装包。
来源、签名、校验或支持范围不明时停止，不使用随机镜像或所谓万能安装包。

本文整理时只读查阅的官方入口：

- [TrollStore](https://github.com/opa334/TrollStore)
- [TrollStore 官方 README 指向的安装指南](https://ios.cfw.guide/installing-trollstore/)
- [TrollRestore](https://github.com/JJTech0130/TrollRestore)
- [普通 Dopamine](https://github.com/opa334/Dopamine)
- [Dopamine RootHide](https://github.com/roothide/Dopamine-roothide)
- [RootHide 开发与环境说明](https://github.com/roothide/Developer)

链接是核验入口，不是自动授权下载、执行或安装；不在总教程固定“永远最新”的
兼容范围。若企业安全软件阻止工具，遵循授权审查，不自行停用防护或加排除。

## 五、阶段 1：源机只读，确认目标覆盖范围

换机配置恢复采用**源机只读、目标机覆盖**：只从源机读取和导出，不上传助手、
不安装、不修改源配置、不发送通知或重载。只覆盖本轮清单内兼容的设置文件
或设置部分，不强制保存目标旧配置，不要求 Mac／手机双端备份。源机不是
目标旧状态的备份；未另存旧状态时，失败后按源候选修正，不承诺回滚。

下述四层备份用于另行授权的完整灾备、抹机或移除越狱环境，不是每次插件／
设置对齐的前置门槛；已有备份及历史证据不因规则调整而删除。

### 1.1 另行完整灾备时准备空间

估算 Finder 备份、媒体原件、IPA／DEB、临时工作副本的总量，并预留操作空间。
有大量照片时使用足够容量、适合大文件且权限可控的外置存储；敏感备份应加密。
`du -sh /var/jb` 在映射环境可能误导，不能只凭这一项判断够不够空间。

推荐每轮独立保存：

```text
<private-backup-root>/<run-id>/
├── finder-encrypted-backup/
├── photos-originals/
├── jailbreak-packages/
├── trollstore-apps/
└── inventories-and-checksums/
```

尚未越狱的新目标不具备 SSH；不能为了获取越狱层备份先假设已有 root 权限。
源机可用时从源机盘点，目标的原生备份先用 Finder 完成。

### 1.2 完整灾备的四层职责和完成门槛

| 层 | 要保留什么 | 怎么验收 |
| --- | --- | --- |
| 加密 Finder 备份 | 支持范围内的原生设置、App 数据、健康等；加密备份可涵盖更多敏感数据 | Finder 管理备份显示正确设备、时间、加密状态；备份完成且无错误；用户知道密码 |
| 媒体原件独立导出 | 本地完整原件、照片／视频、Live Photo 两部分及必要元数据 | 明确云端未下载原件、隐藏／编辑项范围；文件数、字节、SHA-256及抽查完整性 |
| 越狱层归档 | 包 ID／精确版本／架构／依赖、源、原包、已安装文件清单、Filter、偏好、布局／CC／隔离基线 | 有清单和文件哈希；能区分配置、状态和授权；缺失原包明确记录 |
| TrollStore 层 | 精确 Bundle ID、版本／Build、来源、原 IPA或授权 App bundle、必要扩展和标记 | IPA 结构、哈希、主程序／扩展完整；来源和缺失项清楚 |

注意：

- 加密 Finder 备份不是越狱环境、DEB 和 TrollStore IPA 的完整副本。
- iCloud Photos／优化存储、同步中的 App 数据可能不在本地备份中；确认对应
  Apple 同步恢复路径，不把 DCIM 文件数当全部照片库备份证明。
- 原件哈希一致只证明文件复制完整，不证明相册顺序、编辑结果或完整图库恢复。
- Apple ID、设备密码和生物识别不是可直接复制的插件配置。
- 不直接覆盖 `Photos.sqlite` 或搬高敏 App 沙盒／登录态；这些不属于插件恢复。
- 完成备份不等于已经做过完整灾备演练；没有实际恢复测试时标为未演练。

### 1.3 有旧越狱需要切换时

只有完整备份、支持范围核验和单独授权通过后，才通过旧越狱工具**官方的
移除环境路径**退出旧环境。确认操作只是移除越狱，不是“抹除所有内容”、
Finder 刷机或系统升级。记录工具版本、提示、执行结果及重新启动后的状态。

旧根目录快照是取证／回滚参考，不是恢复模板；不要手工删除随机根、整个
`/var/jb`、dpkg 数据库或系统 App。路径不明确、退出会失去 SSH 时先安排
原生界面／可信 USB 回读，不让连接断开变成无法核验的空窗。

## 六、阶段 2：安装并验证 TrollStore

### 2.1 巨魔已经正常就跳过安装器

先在手机确认 TrollStore 可打开、设置页正常、Persistence Helper 状态。
有图标但不能启动时，先按已配置 Helper／官方注册恢复路线处理，不直接覆盖。

### 2.2 本次 USB 路线：TrollRestore → Helper → TrollStore

在安装器和系统确实匹配、用户明确同意写入时：

1. 使用已核对的官方 TrollRestore 发布包，固定目标设备。
2. 选择用户同意的可移除系统 App，例如 Tips，作为安装 Helper 承载对象。
3. 执行安装器，保存结果；等待手机正常重启重新上线。
4. 重新确认仍是同一设备，在手机打开 Tips 中的 Helper。
5. 在 Helper 内执行 Install TrollStore，再打开实际 TrollStore App。
6. 在 TrollStore 设置里，配置合适的 **Persistence Helper**，不能省略。
7. 检查安装和持久化状态；必要重启／注册恢复验证必须单独计划，不把图标
   存在或安装器退出 0 写成全部通过。

TrollRestore 更换系统 App 主程序的安装 Helper，不自动等价于正确的持久化
助手。所选 App 的原功能会受到替换影响；恢复承载 App 需按官方卸载／重装
流程另行处理，且先保证不会因此失去唯一恢复入口。

遇到“查找我的 iPhone”、账号或安全保护提示时停止，让用户按官方流程处理；
不自动关闭保护。用户授权临时更改过的保护，在流程结束时安排核对和恢复。
详见 [USB 安装 TrollStore 历史记录](trollstore-usb-install.md)。

### 2.3 阶段通过条件

安装 Helper 已写入、TrollStore 已安装可打开、Persistence Helper 已配置、
当前注册正常，分别确认。只验证前一项不能进入后续并宣称巨魔完整可用。
TrollInstallerX 等其他路线按官方对应指南走，不复用过期企业证书或历史 IPA。

## 七、阶段 3：用巨魔安装越狱 App，再执行越狱

### 3.1 安装越狱 IPA/TIPA

1. 确定使用普通 Dopamine 还是 Dopamine RootHide，不混装／同时激活两个环境。
2. 读取该**具体发布版本**支持范围，核对设备、系统、Build、来源和 SHA-256。
3. 把已核对的 IPA/TIPA交给 TrollStore：从文件中共享／打开到 TrollStore，
   再由 TrollStore 执行安装。
4. 如果当前版本存在，不为“恢复”自动覆盖；版本不同先核对更新策略与备份。
5. 确认安装结果、App 身份和版本，正常打开所选越狱 App。

**到这里仅完成“巨魔安装越狱软件”，仍未完成实际越狱。** 不通过普通 App Store
搜索同名工具，也不从软件源装一份名字相似的 App 来代替所选官方越狱发布包。

### 3.2 在越狱 App 中执行 Jailbreak

1. 在用户可确认的前台界面，核对确实是所选工具／版本及官方步骤。
2. 按该版本要求选择包管理器／设置，然后执行 Jailbreak。
3. 让工具完成其自身引导、重载或重启要求，记录成功或失败信息。
4. 成功后确认本轮启动环境、包管理器、实际根路径和安装包架构。
5. 失败先留结果，按官方故障处理；不无限重试、不手工修补系统目录。

界面具体按钮和版本行为以实际发布包为准。仓库历史记录没有完整保存所有
版本的逐屏越狱画面，因此不编造固定按钮坐标、固定 exploit 选项或“一次必成”。

### 3.3 最小环境验证与连接

- 越狱 App 显示本轮环境状态，包管理器可正常读取包数据库。
- 若本轮需要 SSH，确认在目标环境内已安装／启用受支持的 SSH 服务，再建立
  连接；不用巨魔存在来推断 SSH 必然可用。
- `mobile` 登录和 `sudo` 可以是当前合法路径，不为自动化修改 root 密码。
- SSH 主机密钥严格校验，地址变化后匹配已信任的同一设备身份，不删旧记录
  或关闭校验；USB 转发先查现有端口，别把历史监听当当前设备。
- 读取机型、系统、Build、当前用户、`dpkg --print-architecture`、真实根路径。

后续 SSH 参数和路径核对见 [恢复详细教程第 3、4 节](iphone-restore-step-by-step.md#3-连接两台手机并确认身份)。

```sh
# 这是已建立、已确认越狱 SSH 通道后的只读模板。
ssh -S "$TARGET_SOCKET" "$TARGET_LOGIN" \
  'id; sysctl -n hw.machine; sw_vers; dpkg --print-architecture; readlink -f /var/mobile'
```

普通重启后可能需重新执行越狱；以选定工具的 semi-untethered 行为为准。
不必因未激活重装巨魔、越狱 App、全部插件或恢复整机数据。

## 八、阶段 4：先配置 RootHide 隔离，再用高敏 App

这一阶段针对本流程中的 RootHide 路线，不把普通 rootless 假装成具有同一管理
界面或黑名单语义。RootHide 版本差异应读取实际 Manager／消费者，不能猜。

1. 只读确认目标原配置／原文件不存在状态和相关注入策略，不强制备份。
2. 列出原机已确认目标、当前已安装主 App、实际扩展 Bundle ID；未来新装的
   高敏 App 在第一次启动之前再补检查。
3. 优先官方 Manager 操作。仅本轮明确授权的条目设黑名单；不复制整份原机
   RootHide 配置、清理规则或全局开关，也不写官方禁用且没有消费者的白名单模式。
4. 黑名单是拒绝项，不是允许注入。默认禁止对阿里／蚂蚁、银行／支付／证券和
   京东 App 开启 tweak injection；不得批量放行共享进程或开启全局 UIKit。
5. 配置、原生服务判定及其他高敏／非目标项逐项回读，保留原格式与元数据。

直接文件更新只在官方路径不可用且已明确授权时使用：保持 XML、同目录
暂存、Foundation 可变 `appconfig`、原子发布和失败回滚。普通偏好的 binary
导出不能覆盖 RootHideConfig。官方 writer 的现场属主／权限优先，不硬编码。

**RootHide 黑名单不会移除 TrollFools 写进 App 的 dylib、load command 或其他
旧修改。** 有既有注入的 App 需要独立授权和可恢复的处理方案；不能把
`appconfig=true` 当成它已恢复原装或进程完全纯净。
也不承诺黑名单能清除服务器风控或保证检测不到越狱。

详细流程与原生查询工具见 [恢复详细教程第 13 节](iphone-restore-step-by-step.md#13-后续补齐阿里蚂蚁黑名单)
以及 [设备配置安全规范](../DEVICE_CONFIG_SAFETY.md)。

## 九、阶段 5：恢复 App，再计算最终布局

### 5.1 安装渠道按来源分流

| 类别 | 恢复路线 | 必须分开的范围 |
| --- | --- | --- |
| 普通官方 App／高敏 App | 原生 App Store、用户正常认证 | 安装不等于账号恢复或可注入 |
| 既有合法授权 TrollStore App | 原 IPA，或核对来源后的 App bundle → Payload IPA → TrollStore | 只迁移程序，不搬沙盒／App Group／Keychain |
| VPN App | 按其已授权安装渠道恢复 App 本身 | 账号、节点、订阅、profile 和连通性另行授权与验证 |
| App 内 dylib／TrollFools 修改 | 不作为普通恢复默认项，单独确认目标和权限 | 文件生成、代码允许目标、实际注入、运行有效是四个不同状态 |
| Crane 多开容器 | 单独容器／账号备份和兼容审查 | 不能把 craneprefs 复制当成容器数据恢复 |

普通 App Store 请求步骤见 [App Store 专项教程](native-app-store-download.md)。
当前 GUI 权限门禁失败时停止自动化，不用历史 HID 助手绕过；可由用户在官方
界面正常操作，不冒充自动化已验收。遇到账户、付款或身份提示交给用户。

### 5.2 TrollStore App 恢复核对

只安装明确缺失的 App。源 IPA／App bundle核对 Bundle ID、版本／Build、
必要主程序／扩展、架构及来源；目标已经有 App 就停止覆盖分支，不能先卸载。
RootHide shell 暂存与 TrollStore 原生 helper路径可能不同，按当前命名空间
解析，不硬编码容器／随机根，不通过 force绕过旧应用或兼容问题。

安装后核对注册、版本和扩展完整性；helper返回 0 不证明 App 全部功能正常。
只有用户明确接受具体功能降级且有依据时才处理可选组件，不能为了安装绿色
随便删扩展。完整步骤见 [恢复详细教程第 6 节](iphone-restore-step-by-step.md#6-trollstore-与普通-app-的前置恢复)。

### 5.3 原生数据恢复与媒体恢复

换机／灾备时，Apple原生数据恢复通常先于越狱配置。Finder恢复备份可能还受
目标系统版本、空间、同步状态限制；不要为了读入备份自动升级到不支持越狱的
iOS。苹果刷机／抹机与恢复备份是不同动作，必须分开授权。

独立媒体导出后的导入、去重、顺序、编辑和 Live Photo关联也要单独计划并
回读，不直接替换照片数据库。已有照片先比较最新备份和当前库，删除必须可
逆、具体授权；本次插件恢复并未迁移完整相册／账号数据。

## 十、阶段 6：恢复源、依赖和插件

### 6.1 软件源先保留目标基础源

对比当前 `.sources`／`.list` 的完整语义，包含签名／架构限制等额外字段。
保留目标基础源，覆盖本轮确认的对齐文件；临时校验、同目录原子替换并正式回读，不强制备份。
源登记和成功联网刷新分开验收，不为证书／签名错误关闭 TLS 或强信任未知源。

### 6.2 分批恢复插件

顺序：当前环境必需基础组件 → 所需依赖 → SpringBoard／设置插件 → 普通
App 专属插件。现有 loader／bootstrap优先保留，不用原机基础包覆盖目标。

每个包先检查：版本、架构、依赖、安装和卸载脚本、全部 Filter、Mach-O
依赖、签名与链接。先模拟，确认没有不期望的卸载／升级，再做精确批次安装。

```sh
# 在目标已授权终端；REMOTE_DEB是本轮完整审查过的包，不是任意下载文件。
sudo apt-get -s --no-download install "$REMOTE_DEB"
# 目标范围与安装模拟通过后才执行写入：
sudo dpkg -i "$REMOTE_DEB"
```

不要强忽略架构／依赖，不做无界限 `apt-get -f install` 或全量升级。
RootHide不支持的普通 rootless包，优先匹配原生包或官方 Patcher；转换不是
完整兼容证明。无原包时的按已安装文件清单重建，只是私有恢复包，不是源码
重建或作者官方原包；第三方来源／许可仍需确认。

本次风险样例：Filza脚本删除同名 App、iCleaner清目录、libsandy重启
securityd、120Hz／大屏／长焦能力不能搬到12 mini。详见
[恢复详细教程第 8 节](iphone-restore-step-by-step.md#8-恢复插件与依赖)。

## 十一、阶段 7：覆盖目标设置，区分纯设置与混合偏好

1. 在当前安装版本的设置面板／实际消费者中确定键和默认值。
2. 对应原生API与磁盘读回一致；路径不明先诊断，不用旧目录经验猜。
3. 确认目标格式、属主／模式和覆盖清单，不强制备份目标原配置。
4. 源已保存值按真实值；源未保存值只有两端默认语义一致才补。
5. 兼容的纯设置文件可整文件覆盖；混合域只覆盖设置部分，状态栏用同源 SISettingsStore。
6. 等待落盘，检查候选与API／磁盘一致、清单外及不可迁移字段不变、格式／权限正确，再仅通知目标消费者。

不复制授权、账号／容器、音量快照、命令序号、版本迁移状态、AppData角标
快照或没有当前消费者的旧键。尺寸一样不表示总开关开启：本次 Bolders
`tweakEnabled` 就是需要另核对的例子。原生API落盘前不能用手写文件覆盖缓存。

`settings-key-client` 接受直接键值字典；`tweak-prefs` 的 patch是 `set` 字典和
`remove` 数组。两种契约不能混用，也不能把逐键合并当整文件替换；工具不自动核验版本与权限。
详见 [恢复详细教程第 9 节](iphone-restore-step-by-step.md#9-覆盖目标插件设置)。

## 十二、阶段 8：控制中心和桌面最后恢复

### 8.1 控制中心：消费者先齐，再恢复列表

先查每个模块 bundle的 Info.plist／模块ID；缺模块先补包，不用配置列表
制造不存在的按钮。不要求目标旧配置备份，按源列表调用实际系统版本的原生
ControlCenterServices写入接口覆盖，保存格式／额外键／元数据并回读。

排列、禁用、固定启用是三组数组。恢复列表不测试按钮功能，不为了验收点击
VPN、支付、扫码或改变网络。详见
[恢复详细教程第 10 节](iphone-restore-step-by-step.md#10-恢复控制中心)。

### 8.2 桌面：投影到目标真实 App清单

先读取源 IconOrder、目标真实 IconState、当前 App注册表。按源文件夹／顺序
投影，过滤目标未安装项、保留目标额外 App和小组件，最后生成目标布局标识。
Dock按已安装的对应 App恢复；不复制壁纸、账户和源小组件内部状态。

分别只读核对 IconOrder和系统实际 IconState，目标写入后重载消费者，再读真实
布局。系统重建内部ID可以单独解释，不能忽略重复、遗漏、顺序或文件夹内容。
安装新工具改变图标清单时重新生成候选，不拿旧快照强制覆盖。

源文件夹名可能含 XML控制字符，外部 parser报错不等于原生消费者不能读。
不要删名字“修复”；使用已核对的 Foundation reader／writer并保留生产格式。
详见 [恢复详细教程第 11 节](iphone-restore-step-by-step.md#11-恢复桌面文件夹和-dock)。

## 十三、阶段 9：验证、回滚和收尾

### 9.1 分层验收

| 层 | 最低证据 | 不能偷换成的结论 |
| --- | --- | --- |
| 安装 | 包状态／版本／架构／依赖或 App注册／必要扩展 | 图标存在≠能正常使用 |
| 配置 | 原生API与正式文件符合候选、清单外不变、格式／元数据正确 | 147个目标键一致≠全部系统配置完全相同 |
| 越狱激活 | 本轮工具状态、实际根、包管理器／需要的服务 | 巨魔或越狱App图标≠激活 |
| 运行加载 | 必要重载后的进程／组件映射、布局／CC再读 | 加载映射≠所有Hook功能正常 |
| 视觉与功能 | 当前可见界面、范围内正常功能操作及真实结果 | 黑图或事件返回0≠通过 |
| 隔离 | 主App／扩展策略和原生服务判定、非目标不变量 | 黑名单true≠撤销旧注入或清除风控 |
| 稳定性／功耗 | 明确时间窗、崩溃、CPU／内存／耗电证据 | 短窗口没崩溃≠长期零风险 |

只在本轮已授权、配置回读通过后对目标做必要 `sbreload`，源机不重载。重载不是重启，也不是重新
越狱；正常整机重启后需按该版本处理再激活，不能把重载成功当重启持久化。

### 9.2 断线续跑

检查原 session／PID／设备任务是否仍运行，恢复可信连接后重新确认设备、根
路径、数据库和配置，按实际已落地状态继续。写命令超时不等于没写成功；
先回读再决定，不能重复安装、点下载或覆盖并发用户设置。

### 9.3 分类回滚

- 配置：无目标旧副本时按源候选修正并回读；仅在另有旧副本且无并发编辑时原子恢复，不承诺无备份回滚。
- 原文件不存在：仅撤回本轮新增配置，不能删除用户后续新编辑。
- 包：审卸载脚本与依赖，明确授权后撤回精确包；碰撞文件仅在有旧副本时还原，不覆盖旧全库status。
- App：先确认数据和卸载副作用，不自动删除重装；巨魔App卸载走其官方管理。
- 越狱环境：按对应版本官方禁用／移除方式，不手工删除系统目录或随机根。
- 原生数据／系统恢复：独立灾备操作，不作为插件错误的首选修复，不擅自刷机。

详情见 [恢复详细教程第 14 节](iphone-restore-step-by-step.md#14-断线续跑与回滚)。

### 9.4 清理和长期维护

只清理本轮准确助手、patch和暂存产物，关闭专用socket；保留源导出、恢复清单、已有历史副本、
来源／哈希、回读和故障日志，不用通配符删除其他任务文件，不停止商店下载。
临时关闭过的保护、临时开放的服务由用户授权复核恢复；设备端和Mac端分别说明。

更新iOS前重新核验巨魔／越狱兼容，不能认为旧版本成功就支持新系统。
每次App更新／重装后重新检查高敏主App和新扩展隔离；未来新增项不由旧73条
自动覆盖。插件升级前保留原包和配置，不为追求最新破坏已有依赖。
