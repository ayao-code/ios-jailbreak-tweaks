## 如何对齐

1. **连接可信校验**：先核对 SSH 主机密钥。IP 的旧记录变化时，必须匹配已有
   可信密钥或经用户核验；不能删除旧记录、关闭验证后直接写手机。
2. **当前现场盘点**：读取两台机型、系统、RootHide 命名空间、安装包版本、
   设置面板 Resources plist、偏好文件格式/属主/权限及原生 API 结果。
3. **把设置与状态分开**：纯设置文件可整文件迁移；混合域只取已安装插件的
   白名单设置键。源机已保存的选项
   用实际值；未保存的选项只有两端同版本面板默认值一致才用默认值，不将
   “没保存”直接当成关闭。音量快照、命令序号、授权、账号和容器标识不复制。
4. **源机只读**：读取和导出源设置，在 Mac 整理恢复清单；不写源机，
   不要求备份目标旧配置或在手机另存副本。
5. **目标覆盖**：清单内兼容的纯设置文件允许整文件覆盖，不强制保留目标旧
   设置；混合域仅覆盖可迁移设置。下列工具仍按现有逐键接口工作：
   - 普通域：CFPreferences 的逐键写入/同步。
   - 状态指示：调用同源 `SISettingsStore`，保留锁、原子替换、last-good 和通知。
   - Crane：调用自身 manager 的两个全局界面设置接口，不复制整份 craneprefs。
6. **原格式与元数据**：CFPreferences 若改变 XML/binary 序列化，必须在其
   已落盘相同语义后，使用同目录临时文件恢复原格式与实际属主/权限、原子
   替换，再次做 API/磁盘回读。RootHide 配置始终不碰。
7. **验证及生效边界**：逐域确认候选与目标一致、清单外及不可迁移字段不变、API/磁盘相同，
   已知的 8 组插件发送其确切设置变更通知。未提供实时通知的第三方插件需
   下次正常重载其消费者才完整生效；本轮不擅自重启手机或批量杀业务 App。
8. **最终不变量**：两台 App 注册清单、桌面语义、控制中心配置，以及已取得
   基线的 RootHide/注入策略回读不变；不把没有基线的项目说成已证明。
   本轮参考手机 19 份插件偏好字节不变，左滑返回的触感强度在现场从未保存
   变为 `0`，与目标计划的默认值一致，未向参考手机发出插件配置写入。
   目标尚未取得 RootHide 配置基线，因此不声称已完成其字节不变量证明；
   本次命令没有修改该配置。列出近期崩溃文件，不把文件名检查等同于每个插件
   已功能验证。
9. **收尾**：删除本轮上传的可执行助手及补丁、关闭 SSH 控制连接，保留源导出
   与私有回读记录；已有历史备份不因本次规则调整而删除。公开文档不得包含密码、IP、UDID、容器标识或账号内容。

## 源码与复用

- `scripts/tools/settings-key-client/`：逐键白名单、CFPreferences 客户端、
  状态栏原子存储的同源调用、精确通知、构建脚本。
- `plugins/status-indicators/SISettingsStore.m`：原子配置存储正式源码。
- `scripts/migration/crane-root-settings.m`：Crane 原生全局界面设置接口。
- `app/safe-domain-probe/tools/ui-input/main.m`：独立系统设置 UI 输入变体；
  不向设置或业务 App 注入。这里只用于范围缩减前两项原生系统开关。
- `DEVICE_CONFIG_SAFETY.md`：源机只读、目标覆盖、格式、元数据和回读要求。

旧迁移脚本含历史机型/路径，不可直接重放。每轮重建当前目标、消费者和允许
键计划；设置项相同不意味着屏幕像素效果相同，尤其刘海/灵动岛、文件夹尺寸、
摄像头和高刷新率相关功能。未实测的功能必须单列，不写成“全部完成验收”。
